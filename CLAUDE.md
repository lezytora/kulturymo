# Культуримо — CLAUDE.md

Інструкції для Claude Code. Читай цей файл повністю перед кожною задачею і дотримуйся його. Якщо задача суперечить цьому файлу, спитай, а не вгадуй.

## 0. Формат відповідей

- Do not use Artifacts. Do not wrap code into interactive HTML/React pages or websites. Provide all code, scripts, or text directly in standard markdown code blocks within the chat window.
- Це стосується відповідей у чаті. Файли проєкту (`.html`, `.css`, `.js`) створюй і редагуй у робочій папці як звичайно.

## 1. Про проєкт

- Назва медіа: **«Культуримо»**. Кредо: «Культура ближче, ніж здається».
- Студентське молодіжне онлайн-медіа про культуру Львова та області: замки, фото, Євробачення, кіно, музика, українська література, неординарні люди, культурні експерименти.
- Аудиторія: студенти й молодь 16–30 років, здебільшого з телефона → **mobile-first**.
- Мова сайту й усього контенту: **українська**.
- Тон: живий, сучасний, редакційний, місцями іронічний. Без офіційщини й пафосу.
- Це навчальний проєкт, який має виглядати як справжнє медіа, а не шаблон.

## 2. Дизайн і taste skill

- Для **всіх** візуальних і UI-рішень використовуй встановлений **taste skill**. Перед версткою будь-якої сторінки чи компонента звіряйся з ним.
- Мета: сайт не має виглядати як типовий AI-згенерований лендінг. Ніяких дефолтних градієнтів, однакових карток з тінями, emoji-іконок, центрованих hero з кнопкою «Дізнатися більше».
- Орієнтир: редакційні медіа (сітки, ієрархія заголовків, ритм, багато білого простору).

## 3. Референси (беремо принципи, не копіюємо)

- **hromadske.ua** — структура головної: компактна шапка з меню, великий головний матеріал + вертикальний список свіжого поруч (дата й час біля кожного пункту), далі блоки по рубриках (заголовок рубрики + «До рубрики →» + сітка карток), блок відео, блок із круглими фото людей, великий футер.
- **kulturamedialna.org** — сторінка команди (роль → ім'я → короткий опис), плитки проєктів із тегами-напрямами, багато білого простору, спокійна мінімалістична подача.
- **НЕ копіюй** логотипи, тексти, фото, кольори чи шрифти цих сайтів. Візуальна айдентика має бути власна.

## 4. Стек і технічні обмеження

- Статичний багатосторінковий сайт: **HTML + CSS + vanilla JS**. Без фреймворків, без збірки, без npm-залежностей, без серверної частини.
- JS — ES-модулі (`<script type="module">`). Локально запускати через VS Code Live Server або `npx serve .` (через `file://` модулі не працюють).
- Деплой: **Vercel**, Framework Preset = Other, Build Command і Output Directory порожні. `vercel.json` не потрібен.
- Усі матеріали, автори, рубрики й події лежать **в одному файлі `js/data.js`** (масиви об'єктів). Сторінки рубрик, статей і пошук формуються з цих даних через JS. Додати новий матеріал = додати один об'єкт у масив.
- Динамічні сторінки через query-параметри: `article.html?id=slug`, `rubric.html?id=slug`, `author.html?id=slug`, `search.html?q=запит`. Невідомий id → показати стан «не знайдено» з посиланням на головну.
- Адаптивність: брейкпоінти **360 / 768 / 1280 px**. Жодного горизонтального скролу сторінки (крім навмисних горизонтальних каруселей).
- Шрифти з Google Fonts з підтримкою кирилиці: заголовки **Unbounded**, текст **Inter**; основний текст статей можна **Source Serif 4**.
- Фото й відео поки що **плейсхолдери**: кольорові блоки з градієнтом і підписом «Фото». Кожне місце під фото має правильні пропорції (`aspect-ratio`) і атрибут `alt`, щоб зображення можна було замінити без зміни верстки. Відео: блок із кнопкою Play і заготовкою під YouTube-embed.
- Доступність і SEO: семантичні теги (`header`, `nav`, `main`, `article`, `aside`, `footer`), достатній контраст, видимий `:focus-visible`, `aria-label` на іконках, `<title>`, `description` і Open Graph теги на кожній сторінці, `loading="lazy"` на зображеннях.
- Код коментується **українською** в місцях, які редакція змінюватиме: назва, лого, кольори, рубрики, контент.

## 6. Дані (`js/data.js`)

Експортує: `site`, `rubrics`, `authors`, `articles`, `events`. Орієнтовна схема:

```js
export const site = {
  name: "Культуримо",
  tagline: "Культура ближче, ніж здається",
  year: 2026
};

export const rubrics = [
  { id: "zamky", name: "Замки", color: "#...", description: "...", subtopics: ["..."] }
];

export const authors = [
  { id: "slug", name: "...", role: "...", bio: "...", photo: "" }
];

export const articles = [
  {
    id: "slug",
    title: "...",
    lead: "...",
    rubric: "kino",
    tags: ["..."],
    author: "slug",
    date: "2026-11-03",
    cover: { src: "", alt: "...", caption: "..." },
    video: null,
    featured: false,
    body: [
      { type: "p", text: "..." },
      { type: "h2", text: "..." },
      { type: "quote", text: "..." },
      { type: "gallery", items: [{ src: "", alt: "" }] },
      { type: "video", youtubeId: "" }
    ]
  }
];

export const events = [
  { id: "slug", title: "...", date: "2026-11-05", time: "19:00", place: "...", rubric: "kino", description: "..." }
];
```

- Час читання рахуй автоматично з `body` (~200 слів/хв).
- Дати показуй українською: «3 листопада 2026» (через `Intl.DateTimeFormat("uk-UA")`, прибрати хвіст « р.»).
- Нова рубрика чи підтема має додаватися **одним рядком** у масив `rubrics`, без змін у HTML.

## 8. Дизайн-система

- Фон: білий / теплий off-white. Текст: майже чорний.
- **Один** яскравий акцентний колір: Pantone Nautical Blue (~`#1A5091`) для кнопок, посилань і активних станів. Колористика бренду: чорний, білий, синій.
- Кожна з рубрик має свій колір-мітку (маленька плашка над заголовком картки). Кольори рубрик приглушені й гармонують з основною палітрою, не конкурують з акцентом.
- Усі кольори, шрифти, відступи — CSS-змінні в `:root` на початку `style.css`.
- Типи карток:
  - **L**: велике фото 16:9, великий заголовок, лід;
  - **M**: фото 3:2, заголовок, дата, автор;
  - **S**: без фото, рубрика + заголовок + дата (для списків);
  - **подія**: велика цифра дня, місяць, назва, місце, час.
- Біля кожного матеріалу: дата українською й час читання.
- Hover-ефекти ненав'язливі: легке підсвічування заголовка, невеликий зум фото. Поважай `prefers-reduced-motion`.

## 9. Шапка (на всіх сторінках, sticky)

- Дворядкова.
- Верхній ряд: ліворуч лого + назва «Культуримо» (веде на головну); праворуч пошук і посилання «Що відвідати» та «Про нас».
- Нижній ряд: меню рубрик у порядку зі списку вище. Активна рубрика підсвічена. Якщо пункти не влазять в один рядок, зайві згортаються в «Ще ▾».
- Пошук: іконка лупи, по кліку розкривається поле на всю ширину шапки (Esc закриває). Під час набору з'являється список до 5 підказок (заголовки, теги, рубрики). Enter відкриває `search.html?q=...`.
- Жодних посилань на соцмережі чи пошту в шапці.
- На мобільному: логотип, лупа й бургер-меню (випадна панель на весь екран зі списком рубрик і сторінок).

## 10. Головна сторінка (зверху вниз)

- **A. HERO.** Дві колонки на десктопі (≈ 2/3 + 1/3), на мобільному одна під одною.
  - Ліворуч: головний матеріал (`featured: true`): велике фото або відео (для відео кнопка Play), плашка рубрики, великий заголовок, лід у 1–2 речення, автор, дата.
  - Праворуч: блок «Актуальне» зі списком 5–6 свіжих матеріалів (рубрика, заголовок, дата/час), кожен пункт відділений лінією. Внизу посилання «Усі матеріали →».
- **B. Стрічка рубрик-тегів** під hero: 8 кнопок-чіпсів, кожна веде на свою рубрику. На мобільному горизонтальний скрол.
- **C. Блок «Що відвідати цього тижня»**: заголовок і діапазон дат тижня, 4–6 коротких анонсів подій (дата, назва, місце, час, посилання «Детальніше»). На десктопі сітка, на мобільному горизонтальний скрол. Праворуч від заголовка «Уся афіша →». Тиждень рахується від поточної дати; якщо подій цього тижня менше 4, добираються найближчі майбутні.
- **D. Блоки рубрик.** Усі 8 рубрик оформлені однаково, простими блоками один під одним. Кожен блок: назва рубрики (заголовок з кольоровою міткою), тонка лінія, посилання «До рубрики →» і ряд із 4 карток (1 картка L + 3 картки M на десктопі; на мобільному 1 картка L + список карток S). Картки беруться з `data.js` за рубрикою, найновіші першими.
- **E. Блок «Наша команда»**: короткий тизер (3–4 круглі фото-заглушки, 1–2 речення про редакцію) і кнопка «Познайомитися з командою».
- **F. Футер**: логотип, 1–2 речення про медіа, список рубрик у кілька колонок, посилання «Про нас» і «Що відвідати», рядок «© 2026 Культуримо. Студентське медіа.» Без соцмереж і пошти.

## 11. Інші сторінки

1. **Сторінка рубрики** (шаблон для всіх): назва, короткий опис, чіпси-фільтри за підтемами, один головний матеріал зверху, нижче сітка карток, кнопка «Показати ще». Для «Фоторубрики» замість карток мозаїка фото; для «Експериментів» картки відео з іконкою Play.
2. **Сторінка матеріалу**: рубрика-плашка, заголовок, лід, велике фото з підписом, автор (фото, ім'я, посилання на його профіль), дата, час читання. Основний текст із підзаголовками, цитатами-виносками, галереєю й вбудованим відео. Внизу: теги, блок автора, «Читайте також» (3 картки з тієї ж рубрики).
3. **Що відвідати (афіша)**: усі події списком, згруповані за днями, фільтр за рубрикою.
4. **Про нас / Автори**:
   - вступ: хто ми, місія, чому робимо «Культуримо» (2–3 абзаци + 3 коротких принципи редакції);
   - команда: сітка карток із великим фото, під ним роль (наприклад, авторка рубрики «Кіно», фотографка, дизайнер), ім'я, 1–2 речення про людину;
   - клік на автора відкриває `author.html` зі списком його матеріалів;
   - блок «Долучайся до нас»: як стати автором і форма «Запропонувати тему» (поля: ім'я, повідомлення). Без бекенду: після відправки показується «Дякуємо!».
5. **Пошук** (`search.html`).
6. **404**: з дружнім текстом і посиланням на головну.

## 12. Пошук (деталі реалізації)

Повністю клієнтський, по даних з `data.js`, без бібліотек.

- Шукає по: `title`, `lead`, `tags`, назві рубрики, імені автора, тексту `body`. Події з `events` теж потрапляють у результати окремою групою.
- Нормалізація перед порівнянням (і запиту, і даних): нижній регістр, `trim`, усі апострофи (`'`, `’`, `ʼ`, `` ` ``) зводяться до одного, `ґ`/`г` не змішувати, зайві пробіли схлопуються.
- Запит ділиться на слова; матеріал підходить, якщо містить **усі** слова (AND).
- Ранжування: збіг у заголовку > теги/рубрика > лід > автор > текст. При однаковій вазі новіші вище.
- `search.html` читає `?q=` з URL, підставляє в поле пошуку на сторінці, показує кількість результатів («Знайдено 7 матеріалів» з правильними відмінками: 1 матеріал, 2–4 матеріали, 5+ матеріалів) і підсвічує збіги через `<mark>`.
- Порожній результат: повідомлення «Нічого не знайдено за запитом «…»», підказки (перевір написання, спробуй коротший запит) і чіпси рубрик.
- Порожній запит: показати чіпси рубрик і кілька свіжих матеріалів.
- Підказки в шапці: debounce ~150 мс, до 5 результатів, навігація стрілками ↑↓, Enter відкриває вибраний пункт або сторінку пошуку.
- Екранізуй текст запиту перед вставкою в HTML (ніякого `innerHTML` з сирим вводом).

## 13. Демо-контент

- Заповни сайт тимчасовим українським контентом: мінімум 20 матеріалів (не менше 2 у кожній рубриці), 6 вигаданих авторів, 6 подій на поточний тиждень. Дати матеріалів: жовтень–листопад 2026.
- Автори, герої матеріалів і події вигадані. Про реальні місця (замки, райони міста) пиши лише загальними формулюваннями, без вигаданих дат і історичних фактів. Тексти мають виглядати як справжні (жодного lorem ipsum), але в коді позначай їх коментарем `// ДЕМО: замінити`.
- Матеріали мають відповідати рубрикам: наприклад, репортаж про замок, фотоісторія про вілли, розбір конкурсу Євробачення, рецензія на фільм, пояснення культкоду, відеоопитування студентів, відгук про квартирник, розповідь про неординарну людину, огляд книжки.

## 14. Що НЕ робити

- Не додавай жодних посилань на Instagram чи інші соцмережі, жодних email-адрес. У шапці й футері залиш закоментований блок `<!-- СОЦМЕРЕЖІ — додати пізніше -->`.
- Не додавай новинних рубрик, не пов'язаних з культурою (політика, війна, економіка), рекламні банери, кошик, реєстрацію користувачів, коментарі.
- Не копіюй матеріали референс-сайтів.
- Не підключай фреймворки, npm-пакети, бекенд чи бази даних.
- Не дублюй дані в HTML: усе, що є в `data.js`, рендериться з нього.

## 15. Порядок роботи

Працюй поетапно, після кожного етапу коротко звітуй, що зроблено:

1. `css/style.css` (змінні, база, типографіка, картки) + `js/data.js` з демо-контентом.
2. Шапка й футер у `main.js`, мобільне меню.
3. Головна сторінка.
4. Сторінка рубрики й сторінка матеріалу.
5. Пошук (підказки в шапці + `search.html`).
6. Афіша, Про нас, сторінка автора, 404.
7. Перевірка: 360 / 768 / 1280 px, клавіатурна навігація, відсутність помилок у консолі, Lighthouse.

Після кожної зміни перевіряй, що нічого не зламалося на інших сторінках (шапка, футер, посилання).

## 16. Результат

- Чиста структура файлів з розділу 5.
- Код із коментарями українською: де змінити назву, лого, колір, рубрики.
- `README.md` з описом проєкту, стеком, посиланням на live-демо (Vercel), як запустити локально, і **короткою інструкцією (5–7 рядків)**: як додати новий матеріал, автора, подію, рубрику, як замінити фото.
